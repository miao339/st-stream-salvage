# 流式抢救 · Stream Salvage

一个 SillyTavern 扩展。解决中转站「**服务器生成完了，酒馆却是空白**」的问题。

## 问题长什么样

```
你点了发送 → 酒馆转圈 → 转完了，聊天框空的
```

或者转着转着停了，还是空。

你去中转站的后台看那一条记录，会发现：

```
状态 200    正文 5,570 字    输出 187.8s
```

**字数明明有，说明服务器真的写完了。**

问题出在「送回来」这一步。

## 为什么会这样

部分中转站不是真流式。它先在服务器上把整段写完，最后**一口气**塞进一个超长的 SSE 事件推过来。

这一下如果没推完整——断在字符串中间，或者整条事件连换行收尾都没有——酒馆的流解析器就凑不出一个完整事件：

```js
buffer += chunk;
let lines = buffer.split('\n');
buffer = lines.pop();          // 最后一段当成「半行」扣着
for (const line of lines) {    // ← 数组空了，一次都不执行
    JSON.parse(line);
}
```

**11KB 数据全被扣在缓冲区里，一个 delta 都没解析出来，界面就是空白。**

不是你的设置错了，不是网络问题，也不是预设写坏了。

## 这个插件做什么

在 `window.fetch` 层接管 SSE 响应，按行缓冲：

| 情况 | 行为 |
|---|---|
| 正常流式 | **字节原样透传**，不解析、不改写、不加延迟 |
| 断在行内 | 把残缺尾巴里**已经闭合的字段**捞出来，重新封成合法的 `tool_calls` 事件 + `finish_reason` + `[DONE]` |

具体来说，残缺的 `arguments` 长这样：

```json
{"game_content":"<game>…</comment>","think_nya":"写到一半就断
                    ↑ 已闭合            ↑ 残缺
```

插件会把 `game_content` 完整取出来，丢掉残缺的 `think_nya`，重新打包成一条合法响应。

**实测**：某次真实断流收到 11,253 字节、JSON 断在字符串中间，插件从中救回 **2,604 字**完整正文。

## 安装

进入酒馆的扩展目录：

```bash
cd SillyTavern/data/<你的用户名>/extensions
git clone https://github.com/miao339/st-stream-salvage.git
```

然后重启酒馆，在「扩展」面板里启用 **流式抢救 · Stream Salvage**。

（也可以下载 zip 解压到同一目录。）

## 怎么确认它在工作

断流被救回来时，右上角会弹一条提示：

> 上游断在行内，已从残缺响应里救回 N 字内容

控制台随时可查状态：

```js
__streamSalvage__.status()
// { enabled: true, rescued: 1, lastRescue: {...}, outermost: true, wrapDepth: 1 }
```

## 空回助手

装好之后，酒馆的 **扩展菜单（魔法棒）** 里会多一项 **空回助手**，点开是：

- 这个插件到底在做什么的说明
- **「启用自动抢救」开关**，默认开启；关掉之后插件完全不介入
- 已抢救次数、最近一次结果、当前缓存状态
- 「从缓存立即抢救一次」，可以把上一份抓到的响应手动救进当前聊天

## 和别的插件共存

**只接管聊天补全这一个端点**（`/api/backends/chat-completions/generate`、`/v1/chat/completions` 等），
其它请求（模型列表、存档、图片、世界书、正则）**原样调用，不解析不拷贝**，不会和其它插件抢活。

重包层数上限 3 层。如果你同时用双马尾这类流式防护，两边可以共存：
它在外层时读到的是我们修好的流，我们在外层时先拿原始字节。


## 边界说明

- **只能救「已经推了一部分」的情况**。如果上游只发了心跳、正文一个字都没推，没有东西可救。
- 救回来的内容可能缺尾部字段（比如思考链 `think_nya`），**正文不受影响**。
- 只处理 `content-type: text/event-stream` 的响应，其它请求完全不动。
