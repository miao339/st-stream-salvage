# 流式抢救 · Stream Salvage

一个 SillyTavern 扩展。解决中转站「**服务器生成完了，酒馆却是空白**」的问题。

## 问题长什么样

```
点了发送 → 酒馆转圈 → 转完了，聊天框空的
```

去中转站后台看那条记录，会发现：

```
状态 200    正文 5,570 字    输出 187.8s
```

**字数明明有，说明服务器真的写完了。**

问题出在「送回来」这一步。

## 为什么会这样

部分中转站不是真流式。它先在服务器上把整段写完，最后**一口气**塞进一个超长的 SSE 事件推过来。

这一下如果没推完整——断在字符串中间，或者整条事件连换行收尾都没有——酒馆的流解析器就凑不出一个完整事件，整段丢掉，界面就是空白。

不是你的设置错了，不是网络问题，也不是预设写坏了。

## 插件做什么

**只旁听，不改流。**

```
收到响应 → 用 body.tee() 分出一支，后台自己读完存起来
         → 原响应原样交给酒馆，一个字节都不动
```

也就是说：**不管插件判断对还是错，酒馆收到的内容和没装插件时完全一样。** 最坏情况就是什么都没做，不会让情况更糟。

读到的响应存在内存里。如果发现这份响应里没有 `[DONE]`（说明断流了），会弹提示：

> 检测到断流，打开「空回助手」可救回 N 字

然后你点「从缓存立即抢救一次」，正文就写进当前聊天。

抢救时会从残缺的 `arguments` 里挑出**已经闭合**的字段，丢掉残缺的尾巴，重新包成合法响应：

```json
{"game_content":"<game>…</comment>","think_nya":"写到一半就断
                    ↑ 完整的，救走            ↑ 残缺的，丢掉
```

**实测**：某次断流只收到 11,253 字节、JSON 断在字符串中间，从中救回 **2,604 字**完整正文。

## 怎么用

1. 空回发生了（转圈结束、聊天框空着）
2. **别发下一条消息**——缓存只留最近一份，再发就被覆盖了
3. 点魔法棒菜单里的「空回助手」
4. 按「从缓存立即抢救一次」

面板里还有：开关（关掉后插件完全不介入）、已抢救次数、缓存状态、检查更新。

## 安装

进入酒馆的扩展目录：

```bash
cd SillyTavern/data/<你的用户名>/extensions
git clone https://github.com/miao339/st-stream-salvage.git
```

国内直连 GitHub 常常不通，安装失败就换镜像，内容完全一样：

```
https://ghproxy.net/https://github.com/miao339/st-stream-salvage
https://gh-proxy.com/https://github.com/miao339/st-stream-salvage
https://ghfast.top/https://github.com/miao339/st-stream-salvage
```

装完刷新酒馆，在扩展列表里确认「流式抢救 · Stream Salvage」是开着的。

## 和其他插件共存

**只接管聊天补全这一个端点**（`/api/backends/chat-completions/generate`、`/v1/chat/completions` 等），
其它请求（模型列表、存档、图片、世界书）**原样调用，不解析不拷贝**。

和双马尾这类流式防护插件可以同时开。它的 `window.fetch` 会直接赋值覆盖，所以插件会顺着它保留的 `original` 链检查自己还在不在——**在链里就不动，掉出来了才重包**，不会和它互相抢。

它的破甲、思考等级、会话盐、文风保护、提示词改写全在**请求层**，本插件只在**响应层**旁听，两边不重叠。

## 边界

- **只能救「已经推了一部分」的情况**。如果上游只发了心跳、正文一个字都没推，没有东西可救，只能重 roll 或点站点回放。
- 救回来的内容可能缺尾部字段（比如思考链 `think_nya`），**正文不受影响**。
- 缓存只在内存里，刷新页面就没了。

## 调试

```js
__streamSalvage__.status()
// { enabled, rescued, lastSeen, cached, captureError, outermost, wrapDepth }
```

`cached` 有字节数说明捕获正常；`captureError` 非空会写明卡在哪一步。
